# Git Workflows

Structured branching models that teams use to coordinate development, releases, and hotfixes. You will implement the Gitflow workflow on a sample repository — creating `develop`, `feature/*`, `release/*`, and `hotfix/*` branches and walking through a full feature-to-release cycle. You will then implement a trunk-based workflow on the same repo, working with short-lived feature branches that merge directly to `main`, and compare the two approaches. Finally, you will set up a forking workflow by creating two clones that simulate different developers, each forking and submitting changes via pull requests, and discuss which workflow fits which team size and release cadence.
